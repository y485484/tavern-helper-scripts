# 世界书自动更新

在酒馆游玩长线 RP 时, 角色信息会随剧情发展而变化. 本脚本让你把更新内容交给 AI 输出, 由脚本自动写入世界书的对应条目, 免去手动编辑世界书.

## 安装到酒馆

本脚本以「酒馆助手脚本」的形式运行, 有两种加载方式:

### 方式一: 本地实时开发 (推荐开发时使用)

1. 在项目根目录运行 `pnpm watch`, 保持该终端窗口开启 (它会监听代码变化并自动重新编译, 同时启动 6621 端口的酒馆监听服务);
2. 另外需要一个静态文件服务器把 `dist` 目录暴露到 5500 端口, 例如在项目根目录运行:
   - 有 VSCode Live Server 插件: 右键 `dist/世界书自动更新/index.js` - "Open with Live Server" (端口不是 5500 时请相应修改导入文件里的链接);
   - 无插件: 运行 `npx serve -l 5500 .` (把项目根目录以 5500 端口暴露);
3. 打开酒馆 - 酒馆助手 - 脚本库, 导入 [`导入到酒馆中/世界书自动更新-实时修改.json`](导入到酒馆中/世界书自动更新-实时修改.json:1) (把文件内容粘贴为脚本), 并把脚本内容中的 `localhost:5500` 改为你实际的地址与端口;
4. 启用脚本并刷新酒馆网页, 代码修改后酒馆会自动热重载.

### 方式二: 线上分发 (推荐日常游玩使用)

1. 将项目推送到 GitHub 仓库, 工作流会自动把 `dist` 打包上传 (见 [`bundle.yaml`](.github/workflows/bundle.yaml:1));
2. 在酒馆助手中新建脚本, 内容填写你的 jsdelivr 链接:

```js
import 'https://testingcf.jsdelivr.net/gh/y485484/tavern-helper-scripts@v0.0.3/dist/世界书自动更新/index.js'
```

> 说明: 推荐使用版本 tag 链接 (`@v0.0.3`), 因为 jsdelivr 对 tag 的缓存刷新更快 (12 小时内); 推送新代码后 CI 会自动打新 tag, 建议每次更新后把链接中的版本号换成最新的 (可在仓库的 Actions 页面查看最新运行生成的 tag, 或 `git ls-remote --tags origin` 查看).

## 工作流程

1. 脚本自动把格式说明注入到每次 AI 请求中 (默认开启, 可在设置中关闭, 关闭后需自行把格式放进预设或世界书条目);
2. AI 在回复/总结里按约定格式输出 `<世界书更新>` 标记;
3. 脚本监听到 AI 回复后自动解析标记, 把内容写入目标世界书的对应条目;
4. 也可以点击脚本按钮「重扫世界书更新」, 重新扫描最近若干楼层的更新标记 (处理过的楼层不会重复写入).

> 格式说明通过 `injectPrompts` 注入, 属于「系统」角色的提示词, 插入在聊天末尾 (深度 0), 仅在当前聊天文件中有效; 脚本会在切换聊天时自动重新注入.

## 输出格式

AI 需要在回复末尾输出:

```
<世界书更新>
- 条目: 目标条目的标题 (须与世界书中的条目标题完全一致)
  操作: 替换
  内容: |-
    替换后的完整内容
- 条目: 另一个条目的标题
  操作: 追加
  内容: |-
    追加到该条目末尾的内容
</世界书更新>
```

可用操作:

| 操作 | 说明 |
| --- | --- |
| 替换 | 用「内容」完全替换条目的原有内容, 适合修改角色信息、人设 |
| 追加 | 把「内容」追加到条目末尾, 适合补充经历、事件记录 |
| 前置 | 把「内容」插入到条目开头 |
| 删除 | 删除该条目, 无需填写「内容」 |

## 设置项

脚本设置面板位于「扩展设置」中的「世界书自动更新」抽屉:

- **启用自动更新**: 是否在 AI 回复后自动处理;
- **目标世界书**: 默认「自动」即角色卡绑定的主世界书 (依次回退到附加世界书、聊天世界书); 也可手动指定;
- **条目不存在时自动新建**: 打开后, 更新中提到的、世界书中不存在的条目会被自动创建为蓝灯常量条目; 关闭则跳过并在通知中提示;
- **重扫楼层数**: 点击「重扫世界书更新」时往前检查的楼层数量 (1~100);
- **更新后显示通知**: 是否用通知弹窗汇报写入结果。

## 脚本按钮

在酒馆助手脚本库中为本脚本添加了两个按钮:

- **重扫世界书更新**: 重新扫描最近若干楼层, 处理其中的更新标记 (已处理过的楼层不会重复写入);
- **复制世界书更新格式**: 一键复制格式说明, 可粘贴到世界书条目、预设或总结提示词中, 告诉 AI 该如何输出更新。

## 防重复机制

脚本按「聊天 + 楼层 + 内容哈希」记录处理结果: 同一楼层的相同更新不会被重复写入, 因此重扫是安全的. 若楼层内容被修改且更新标记发生变化, 则会被视为新的更新重新处理.

清空处理记录 (设置面板中的「清空本聊天处理记录」) 后再次重扫会重新处理所有楼层, 其中「追加」类操作可能造成内容重复, 请谨慎使用.

## 常见用法示例

**场景 1: 故事总结时更新角色信息**

在总结提示词中要求 AI: "如果角色人设、关系、状态发生变化, 按 <世界书更新> 格式输出更新, 使用「替换」操作更新对应的角色信息条目."

**场景 2: 记录剧情事件**

要求 AI 在重要事件发生后, 用「追加」操作把事件写入「事件记录」条目.

**场景 3: 角色能力成长**

能力突破后, 用「替换」操作重写「角色能力」条目中的对应部分, 或用「追加」在末尾补充新能力描述.

## 进阶: 在聊天界面上隐藏更新标记

如果不想让 `<世界书更新>` 块显示在楼层里, 可以在酒馆的「正则」-「格式化显示」中新建一条:

- 查找正则表达式: `/<世界书更新>[\s\S]*?<\/世界书更新>/g`
- 替换为: (留空)

这样标记块仍会被正常发送与解析, 只是不会在聊天界面上显示.
